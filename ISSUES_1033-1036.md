# Guard-CLI Issues #1033-1036: Critical Security Regressions

## Overview
This document tracks four critical regression bugs in Guard-CLI that cause silent false negatives in the security scanner. These are deploy-gating failures: the CLI reports "No issues found" with exit code 0 even when security vulnerabilities exist or the scan degrades. All four issues affect production security posture and should be treated as **P0 critical bugs**.

## Issue #1036: Path Filtering Silently Skips All Files in `target/` or `.git/` Parent Directories

**Type:** Critical Security Bug (Silent False Negative)  
**Priority:** P0  
**Regression:** Always present (design bug)  
**Component:** `crates/analyzer/src/lib.rs` (collect_rust_paths)

### Problem
The analyzer rejects **any project** located under a directory named `target` or `.git`, scanning 0 files and exiting with code 0 and "No issues found". A contract deployed from `~/target/my-contract`, `/srv/target/deploy`, or a crate vendored into another workspace's `target/` directory will pass the security gate with **zero scrutiny**.

This is a **silent false negative** in a **deploy-gating security tool** — the worst class of failure.

### Root Cause Analysis

#### Current Broken Behavior (Line References)

**Location:** `crates/analyzer/src/lib.rs:collect_rust_paths()`

```rust
// Current broken implementation
pub fn collect_rust_paths(root: &Path, ignored_dirs: &[String]) -> Vec<PathBuf> {
    WalkDir::new(root)
        .into_iter()
        .filter_entry(|e| {
            let path = e.path();
            
            // BUG: is_ignored_path gets the ABSOLUTE path from WalkDir
            // If root = "/home/user/target/my-contract"
            // Then path = "/home/user/target/my-contract/src/lib.rs"
            // is_ignored_path sees "target" in the path and rejects EVERYTHING
            !is_ignored_path(path, ignored_dirs) && !is_hidden(e)
        })
        .filter_map(Result::ok)
        .filter(|e| e.path().extension().map_or(false, |ext| ext == "rs"))
        .map(|e| e.path().to_path_buf())
        .collect()
}

fn is_ignored_path(path: &Path, ignored_dirs: &[String]) -> bool {
    path.components().any(|comp| {
        if let Component::Normal(os_str) = comp {
            let name = os_str.to_string_lossy();
            // Rejects ANY path containing "target" or ".git" as a component
            name == "target" || name == ".git" || ignored_dirs.contains(&name.to_string())
        } else {
            false
        }
    })
}
```

**Why This Fails:**

1. **WalkDir yields absolute paths:** If the user runs `guard-cli scan ~/target/my-contract`, WalkDir yields paths like `/home/user/target/my-contract/src/lib.rs`
2. **is_ignored_path checks ALL components:** It sees `target` as a component and rejects the path
3. **Every file is filtered out:** Result: 0 files scanned, exit 0, "No issues found"
4. **Vulnerable contracts pass security gates**

#### Correct Behavior Example (scan_files already has this)

**Location:** `crates/analyzer/src/lib.rs:scan_files()` (line ~600)

```rust
// CORRECT implementation in scan_files
let files_to_scan: Vec<PathBuf> = files
    .into_iter()
    .filter(|path| {
        // ✓ CORRECT: Strip the root prefix first
        let relative = path.strip_prefix(&root).unwrap_or(path);
        
        // Now check the RELATIVE path, not the absolute path
        !is_ignored_path(relative, &ignored_dirs)
    })
    .collect();
```

**Why This Works:**

1. **Strip root prefix:** `/home/user/target/my-contract/src/lib.rs` becomes `src/lib.rs`
2. **Check relative path:** `src/lib.rs` has no `target` component (relative to project root)
3. **Files are scanned correctly**

**Location:** `crates/analyzer/src/lib.rs:is_relevant_watch_path()`

```rust
// File: crates/analyzer/src/lib.rs

pub fn collect_rust_paths(root: &Path, ignored_dirs: &[String]) -> Result<Vec<PathBuf>, String> {
    let canonical_root = root.canonicalize().unwrap_or_else(|_| root.to_path_buf());
    
    let paths: Vec<PathBuf> = WalkDir::new(&canonical_root)
        .into_iter()
        .filter_entry(|e| {
            let path = e.path();
            let relative = path.strip_prefix(&canonical_root).unwrap_or(path);
            !is_ignored_path(relative, ignored_dirs) && !is_hidden(e)
        })
        .filter_map(Result::ok)
        .filter(|e| e.path().extension().map_or(false, |ext| ext == "rs"))
        .map(|e| e.path().to_path_buf())
        .collect();
    
    // FIX: Warn if we found no Rust files
    if paths.is_empty() {
        // Check if the project actually has .rs files
        let any_rs_files = WalkDir::new(&canonical_root)
            .into_iter()
            .filter_map(Result::ok)
            .any(|e| e.path().extension().map_or(false, |ext| ext == "rs"));
        
        if any_rs_files {
            return Err(format!(
                "Warning: Found .rs files but all were filtered out. \
                 Check if project is under a 'target' or '.git' directory."
            ));
        }
    }
    
    Ok(paths)
}
```

## Issue #1033: Check Panics Are Silently Discarded

**Type:** Critical Security Bug (Degraded Scan)  
**Priority:** P0  
**Regression:** #659 (marked closed but incomplete)  
**Component:** `crates/cli/src/main.rs`

### Problem
When a security check panics on a file, the analyzer catches the panic and continues, but the CLI binds the panic report as `_check_panics` and **never uses it**. The scan completes with exit code 0 and "No issues found" even though checks **failed to run** on some files. This is a **degraded scan** masquerading as a clean result.

### Root Cause Analysis

**Location:** `crates/cli/src/main.rs:139`

```rust

fn output_human(
    results: &[Finding],
    files_scanned: usize,
    files_skipped: usize,
    check_panics: &[CheckPanic],
) {
    println!("\n{}", "=".repeat(60));
    println!("Guard-CLI Security Scan Results");
    println!("{}", "=".repeat(60));
    
    // Report panics FIRST (most critical)
    if !check_panics.is_empty() {
        println!("\n⚠️  WARNING: Some checks failed to complete:");
        println!("{}", "-".repeat(60));
        
        for panic in check_panics {
            println!("  File: {}", panic.file.display());
            println!("  Check: {}", panic.check_name);
            println!("  Error: {}", panic.panic_message);
            println!();
        }
        
        println!("⚠️  Scan results are INCOMPLETE. Fix check errors and re-scan.");
        println!("{}", "-".repeat(60));
    }
    
    // Then report findings
    if results.is_empty() {
        if check_panics.is_empty() {
            println!("\n✓ No issues found");
        } else {
            println!("\n✗ No issues found, but scan was degraded");
        }
    } else {
        println!("\n✗ Found {} issue(s):", results.len());
        for finding in results {
            println!("\n  [{}] {}", finding.severity, finding.rule_id);
            println!("  {}", finding.message);
            println!("  → {}:{}:{}", 
                finding.location.file.display(),
                finding.location.line,
                finding.location.column
            );
        }
    }
    
    // Stats
    println!("\n{}", "-".repeat(60));
    println!("Files scanned: {}", files_scanned);
    println!("Files skipped: {}", files_skipped);
    if !check_panics.is_empty() {
        println!("Check failures: {}", check_panics.len());

}
```

## Issue #1035: CLI Reports Only One Error from Multi-File Scans

**Type:** DX Regression  
**Priority:** High  
**Regression:** #629 (incomplete implementation)  
**Component:** `crates/cli/src/main.rs` (scan_directory_with_checks)

### Problem
The CLI calls `scan_directory_with_checks`, which uses `.collect::<Result<Vec<_>, ScanError>>()?` with Rayon's parallel iterator. pub fn scan_directory_with_checks(
```rust
    root: &Path,
    checks: Vec<Box<dyn SecurityCheck>>,
    ignored_dirs: &[String],
) -> Result<(Vec<Finding>, usize, usize, Vec<CheckPanic>), ScanError> {
    let files = collect_rust_paths(root, ignored_dirs)?;
    let files_scanned = files.len();

    let raw_results: Vec<Result<(Vec<Finding>, Vec<CheckPanic>), ScanError>> = files
        .par_iter()
        .map(|file| scan_file_with_checks(file, &checks))
        .collect();  // No ? here - collect everything
    
    // Then use collect_scan_results to aggregate
    let mut all_findings = Vec::new();
    let mut all_panics = Vec::new();
    let mut errors = Vec::new();
    
    for result in raw_results {
        match result {
            Ok((findings, panics)) => {
                all_findings.extend(findings);
                all_panics.extend(panics);
            }
            Err(e) => errors.push(e),
        }
    }

        errors.sort_by(|a, b| format!("{:?}", a).cmp(&format!("{:?}", b)));
```

```rust
    }

    let rules: Vec<serde_json::Value> = rules_map.into_values().collect();
    
    // ... build SARIF with rules ...
}

fn build_sarif_rule(finding: &Finding) -> serde_json::Value {
    let help_uri = finding.rule_url
        .as_ref()
        .map(|s| s.as_str())
        .unwrap_or("https://github.com/SorobanGuard/Guard-CLI/blob/main/docs/checks.md");
    
    json!({
        "id": finding.rule_id,
        "shortDescription": {
            "text": get_rule_short_description(&finding.rule_id)
        },
        "fullDescription": {
            "text": get_rule_full_description(&finding.rule_id)
        },
        "helpUri": help_uri,
        "properties": {
            "security-severity": severity_to_score(finding.severity).to_string()
        }
    })
}
```
