# Guard-CLI Issues #1037-1040: CLI Output and Error Handling Fixes

## Issues Overview

### Issue #1037: --watch --markdown clears terminal incorrectly
**Problem**: Watch mode clears the screen for `--markdown` output, but markdown is a structured format and shouldn't have the terminal cleared.

**Location**: `crates/cli/src/main.rs:530`

**Current Code**:
```rust
let should_clear = !no_clear && !json && !sarif && output.is_none() && stdout_is_tty;
```

**Fix**: Add `!markdown` to the condition, or better yet, create an `is_structured` boolean derived from format flags.

**Expected Behavior**: `--markdown` is treated like other structured formats; no clear is sent.

**Acceptance Criteria**:
- Add `!markdown` to `should_clear` (or use a single `is_structured` bool)
- Unit-test the predicate as a pure function

---

### Issue #1038: watch mode ignores edits to soroban-guard.toml
**Problem**: Config and active_checks are loaded once before the watch loop. Only `.rs` events trigger re-scans, so editing `soroban-guard.toml` has no effect until restart.

**Location**: `crates/cli/src/main.rs:259` - `is_relevant_watch_path` only checks for `.rs` files

**Current Code**:
```rust
fn is_relevant_watch_path(path: &Path) -> bool {
    path.extension().is_some_and(|extension| extension == "rs") && !is_ignored_path(path)
}
```

**Fix**: 
1. Make `soroban-guard.toml` trigger re-scans
2. Reload config and rebuild active_checks when config file changes

**Expected Behavior**: Changes to `soroban-guard.toml` take effect immediately in watch mode.

---

### Issue #1039: malformed soroban-guard.toml bypasses --json error envelope
**Problem**: When no path argument is given, the first config load prints plain-text error with `eprintln!` and calls `exit(2)` directly, bypassing the JSON error envelope that `--json` users expect.

**Location**: `crates/cli/src/main.rs:329` - `config_for_default` error branch

**Current Code**:
```rust
Err(e) => {
    eprintln!("{} {}", "error:".red().bold(), e);
    std::process::exit(2);
}
```

**Fix**: Replace with `emit_setup_error(&e.to_string(), json)` to properly handle JSON output.

**Expected Behavior**: `soroban-guard scan --json` with broken config writes JSON error envelope to stdout.

---

### Issue #1040: --sarif/--markdown --output write no file on scan errors
**Problem**: Issue #669 fixed `--output` for scan errors but only in the `opts.json` branch. With `--sarif --output` or `--markdown --output`, parse errors print to stderr but never create/overwrite the output file.

**Location**: `crates/cli/src/main.rs:146` region - error handling in `Err(e)` branch

**Current Code**:
```rust
if opts.json {
    // ... writes error document to output file
} else {
    for message in &messages {
        eprintln!("{} {}", "error:".red().bold(), message);
    }
}
```

**Fix**: Write error documents for SARIF and markdown formats when scan errors occur, similar to how JSON is handled.

**Expected Behavior**: 
- `--sarif --output results.sarif` creates an error SARIF document on parse errors
- `--markdown --output results.md` creates an error markdown document on parse errors
- Prevents "file not found" errors in CI upload steps
- Prevents stale files from previous runs being uploaded

---
